# Архитектура системы сборки

## Цель
Кросс-платформенная сборка Docker-образов для ROS2-пакетов с поддержкой CUDA
под три платформы, с публикацией в реестр и автоматизацией через CI/CD.

## Целевые платформы
| Платформа | CPU | GPU (compute cap.) | Базовый образ | Стек |
|-----------|-----|--------------------|---------------|------|
| x86_64 + NVIDIA dGPU | x86_64 | зависит от карты (RTX 4060 = sm_89) | `nvidia/cuda:12.6.2-devel-ubuntu22.04` | ROS2 Humble |
| Jetson AGX Orin (JP 6.2.2 / L4T R36.5.0) | ARM64 | Ampere sm_87 | `nvcr.io/nvidia/l4t-*` (r36.x) | ROS2 Humble |
| Jetson Orin Nano (JP 7) | ARM64 | Ampere sm_87 | `nvcr.io/nvidia/l4t-*` (JP7) | ROS2 Humble |

Ключевое различие: x86 использует настольные образы `nvidia/cuda`, а Jetson —
L4T-образы NVIDIA (`nvcr.io/nvidia/l4t-*`), привязанные к версии JetPack.
CUDA-архитектура (`sm_*`) различается и передаётся в сборку аргументом
`CUDA_ARCHITECTURES`.

## Стратегия сборки (двухслойная)
1. **Базовые образы** (`docker/base/<platform>/`) — ROS2 Humble + CUDA Toolkit +
   системные зависимости. Собираются и публикуются отдельно.
2. **Слой пакета** (`docker/package/`) — универсальный Dockerfile, собирает
   ROS2-пакет ПОВЕРХ выбранной базы (`ARG BASE_IMAGE`). Один шаблон на все платформы.

## Кросс-компиляция ARM64 (Jetson)
Два способа:
- **Нативно** на ARM64-раннере (GitHub предоставляет ARM-раннеры).
- **Кросс** на x86 через `docker buildx` + QEMU (эмуляция ARM64) либо
  официальные контейнеры NVIDIA.

Замечание: эмуляция CUDA-сборки через QEMU медленная, поэтому тяжёлые сборки
предпочтительно выполнять на раннерах CI, а не локально (особенно в VM).

## CUDA и её подтверждение
FAST-LIO2 сам по себе CPU-only, но образы содержат полный CUDA-стек.
Подтверждение наличия CUDA — на уровне сборки:
- `nvcc --version`;
- наличие библиотек в `/usr/local/cuda/lib64`;
- компиляция тестового `.cu` (`tests/cuda-smoke/vector_add.cu`).

Рантайм на GPU требует хоста с видеокартой и `nvidia-container-toolkit`.

## CI/CD
GitHub Actions (`.github/workflows/build.yml`): сборка базы и пакета, публикация
в ghcr.io. Планируемое расширение: матрица (3 платформы × 2 типа сборки),
кеширование слоёв, запуск smoke-теста как проверки.
